  <action>
    Create `src/components/PlanIntakeModal.jsx` -- a React component that renders a Dialog modal for plan intake.

    **Props:** `{ open, onOpenChange }`

    **Data access:** Call `useAppData()` to get `hierarchicalPlan`, `runnerProfile`, `activities`, `workoutEntries`.

    **Local state:**
    - Form fields: `raceName` (string), `raceDate` (string), `goalDistance` (string), `weeklyKm` (number|""), `daysPerWeek` (string), `hardDays` (string[]), `restDay` (string), `background` (string)
    - `showConfirmReplace` (boolean) -- shows replace confirmation when plan exists
    - `errors` (object) -- field-level validation errors keyed by field name

    **Pre-fill logic (useEffect on mount / when modal opens):**
    1. `background`: If `runnerProfile.background` is truthy, set as default.
    2. `weeklyKm`: Compute from `activities.activities` -- sum distances from last 4 weeks, divide by 4, convert metres to km (`distance / 1000`), round to nearest integer. Only include activities where `type === "Run"`. If no activities, leave empty.
    3. `hardDays` / `restDay`: From `workoutEntries.entries` -- filter entries where `workout_type` is NOT in `["Easy", "Recovery", "Rest"]` and map to day-of-week names for hard days. Filter entries where `workout_type === "Rest"` and take the first day-of-week name for rest day.

    **Day-of-week helper:** Convert a date string to day name using `new Date(dateStr).toLocaleDateString("en-US", { weekday: "long" })`.

    **Form layout (per 18-UI-SPEC.md):**

    Inside `DialogContent` with `className="sm:max-w-lg"`:

    When `generating === false` AND `showConfirmReplace === false`:
    - `DialogHeader` with `DialogTitle` "Build Your Training Plan" and `DialogDescription` "Tell us about your goal and schedule. Claude will design a personalized plan."
    - **Field Group 1 -- Race Goal:**
      - Label "Target Race" + Input text for `raceName`
      - Label "Race Date" + Input type="date" for `raceDate` (REQUIRED -- error: "Race date is required.")
      - Label "Goal Distance" + Select with options: "5K", "10K", "Half Marathon", "Marathon" (REQUIRED -- error: "Please select a goal distance.")
    - **Field Group 2 -- Fitness Baseline:**
      - Label "Current Weekly Volume (km)" + Input type="number" for `weeklyKm` (REQUIRED -- error: "Enter your approximate weekly km.")
      - If pre-filled from Strava: show muted 12px text below: "Estimated from your recent Strava activities."
    - **Field Group 3 -- Weekly Constraints:**
      - Label "Training Days Per Week" + Select with options: "3", "4", "5", "6" (REQUIRED -- error: "Select how many days you can train per week.")
      - Label "Preferred Hard Days" + multi-checkbox or multi-select for day names (Monday through Sunday). Store selected values in `hardDays` array.
      - Label "Rest Day" + Select with day name options (Monday through Sunday) for `restDay`.
    - **Field Group 4 -- Background:**
      - Label "About Your Running Background" + Textarea with 4 rows min, placeholder "E.g. Running 3 years, completed one half marathon, struggle with long easy paces..."
      - If pre-filled from runner profile: show muted 12px text below: "Loaded from your runner profile."
    - If `hierarchicalPlan.plan !== null`, show a destructive-colored warning box: "This will replace your current plan."
    - `DialogFooter` with Button variant="outline" "Back to Plan" (calls `onOpenChange(false)`) and Button variant="default" "Generate Plan" (calls `handleSubmit`).

    **Validation (on submit, NOT on blur):**
    - Required fields: `raceDate`, `goalDistance`, `weeklyKm`, `daysPerWeek`.
    - If any required field is empty, set `errors` object with field name keys and error message values. Return without submitting.
    - Clear errors when field value changes (use onChange handlers that also clear the specific error).

    **Submit flow (`handleSubmit`):**
    1. Run validation. If fails, return.
    2. If `hierarchicalPlan.plan !== null` AND `showConfirmReplace === false`:
       Set `showConfirmReplace = true` and return (show confirmation view).
    3. Construct `AthletePayload`:
       ```javascript
       const payload = {
         raceGoal: {
           eventName: raceName || goalDistance,
           eventDate: raceDate,
           eventType: mapDistanceToEventType(goalDistance),
           // mapDistanceToEventType: "5K"|"10K" => "road", "Half Marathon" => "half_marathon", "Marathon" => "marathon"
         },
         fitness: {
           weeklyKm: Number(weeklyKm),
           longestRun: 0,  // not collected in form -- default
           lthr: 0,        // not collected in form -- default
           yearsRunning: 0, // not collected in form -- default
         },
         constraints: {
           longRunDay: "Sunday", // default
           hardDays: hardDays,
           restDays: restDay ? [restDay] : [],
           maxSessions: Number(daysPerWeek),
         },
         background: background,
       };
       ```
    4. Call `await hierarchicalPlan.generatePlan(payload)`.
    5. On success: call `onOpenChange(false)` to close modal.
    6. On error: error is already in `hierarchicalPlan.error` via hook state.

    **Confirmation sub-state (`showConfirmReplace === true`):**
    - Replace the form body with:
      - Warning text: "You already have an active plan. Generating a new one will permanently replace it."
      - Two buttons: Button variant="outline" "Go Back" (sets `showConfirmReplace = false`) and Button variant="destructive" "Replace and Generate" (calls `handleConfirmReplace`).
    - `handleConfirmReplace` function: constructs the AthletePayload (same as step 3 above) and calls `hierarchicalPlan.generatePlan(payload)` directly, bypassing the confirmation check.

    **Generating state (`hierarchicalPlan.generating === true`):**
    - Replace the form body with centered spinner:
      - `DialogTitle` changes to "Building Your Plan..."
      - Centered `Loader2` icon from lucide-react with `animate-spin` class, size `h-10 w-10`, color `text-primary`, inside an 80x80px container (`flex items-center justify-center` with `h-20 w-20`).
      - Rotating coaching message: cycle through `["Analyzing your fitness...", "Structuring your phases...", "Building your weekly plan..."]` using `useState` + `useEffect` with a `setInterval` every 4 seconds.
      - Static subtext: "This usually takes 30-60 seconds." in 12px muted text.
    - Footer is hidden during generating state.
    - Modal cannot be dismissed: pass `onInteractOutside={(e) => e.preventDefault()}` and `onEscapeKeyDown={(e) => e.preventDefault()}` to `DialogContent` when `generating === true`.

    **Error state:**
    - If `hierarchicalPlan.error` is truthy and `generating === false`, show error text below the form: "Plan generation failed. Check your connection and try again." in `text-destructive` styling.

    **Accessibility (per 18-UI-SPEC.md):**
    - All form fields have `Label` with correct `htmlFor` / `id` pairing.
    - `aria-live="polite"` on the rotating message container.
    - During generating: form fields get `aria-disabled="true"`.
    - Min touch target: `min-h-[44px]` on all Button and Input components.

    **Styling (per 18-UI-SPEC.md):**
    - Pre-filled fields: background `bg-muted` with italic text.
    - Error messages: `text-destructive text-xs` below the field.
    - Section gaps between field groups: `space-y-6` on outer container, `space-y-4` within groups.
    - Warning banner: `bg-destructive/10 border border-destructive/20 text-destructive rounded-md p-3 text-sm`.

## Modal Anatomy: PlanIntakeModal

The intake modal has two distinct visual states: **form state** and **generating state**. These are mutually exclusive and driven by the `generating` flag from `useHierarchicalPlan`.

### State 1 — Form State (`generating === false`)

Layout (top to bottom inside `DialogContent`):

```
┌─────────────────────────────────────────────┐
│ DialogHeader                                  │
│   DialogTitle: "Build Your Training Plan"     │
│   DialogDescription: [subtitle]               │
├─────────────────────────────────────────────┤
│ Field Group 1: Race Goal                      │
│   Label: "Target Race"                        │
│   Input: race name / event name               │
│   Label: "Race Date"                          │
│   Input[type=date]: race date                 │
│   Label: "Goal Distance"                      │
│   Select: 5K / 10K / Half Marathon / Marathon │
├─────────────────────────────────────────────┤
│ Field Group 2: Fitness Baseline               │
│   Label: "Current Weekly Volume (km)"         │
│   Input[type=number]: pre-filled from Strava  │
│   [pre-fill notice: muted 12px text]          │
├─────────────────────────────────────────────┤
│ Field Group 3: Weekly Constraints             │
│   Label: "Training Days Per Week"             │
│   Select: 3 / 4 / 5 / 6                      │
│   Label: "Preferred Hard Days"                │
│   Select (multi or checkboxes): day names     │
│   Label: "Rest Day"                           │
│   Select: day names                           │
├─────────────────────────────────────────────┤
│ Field Group 4: Background                     │
│   Label: "About Your Running Background"      │
│   Textarea: free text, 4 rows min             │
│   [pre-fill notice if runnerProfile.background exists] │
├─────────────────────────────────────────────┤
│ [Replace warning banner — only when plan exists] │
│   Destructive-colored box:                    │
│   "This will replace your current plan."      │
├─────────────────────────────────────────────┤
│ DialogFooter                                  │
│   Button variant="outline": "Back to Plan"    │
│   Button variant="default": "Generate Plan"   │
└─────────────────────────────────────────────┘
```

### State 2 — Generating State (`generating === true`)

When `generatePlan()` is called, the form fields are replaced with a centered loading display. The modal remains open (not dismissible during generation — `DialogContent` should not close on overlay click while `generating === true`).

```
┌─────────────────────────────────────────────┐
│ DialogHeader                                  │
│   DialogTitle: "Building Your Plan..."        │
├─────────────────────────────────────────────┤
│ [Centered spinner — 80×80px]                  │
│                                               │
│ [Rotating coaching message — 16px, muted]     │
│   e.g. "Analyzing your fitness..."            │
│                                               │
│ [Static subtext — 12px, muted]                │
│   "This usually takes 30–60 seconds."         │
└─────────────────────────────────────────────┘
```

The footer is hidden during generating state. No Back to Plan button while Claude is processing.

### Confirmation Sub-State (replace existing plan)

When the user submits and a plan already exists, before calling `generatePlan()`:
- Modal does NOT close
- A confirmation section appears below the form (or the form collapses) showing:
  - Warning: "You already have an active plan. Generating a new one will permanently replace it."
  - Two buttons: "Go Back" (outline) and "Replace and Generate" (destructive variant)

## Accessibility Contract

- All form fields have an associated `<Label>` with correct `htmlFor` / `id` pairing
- `DialogTitle` is always rendered (not conditionally hidden) for screen reader modal announcement
- `aria-describedby` on `DialogContent` points to the description text
- Spinner state: `aria-live="polite"` on the rotating message container so screen readers announce message changes
- During generating state: form fields have `aria-disabled="true"` and `tabIndex={-1}` to prevent focus
- Minimum touch target: 44px height on all interactive elements
- Focus trap: handled automatically by `@radix-ui/react-dialog`
- Escape key: closes modal in form state; blocked in generating state
